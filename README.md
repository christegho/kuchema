# Kuchema

A local collage tool for *Kuchema: The Gathering*. React, Express, Sharp and a local YOLO/SAM worker. No accounts or collections. Deployment is deferred.

[Development explorations, research and references](development-notes.md)

[TouchDesigner integration guide](touchdesigner.md)

## Run

```sh
npm install
npm run setup:vision
npm run dev
```

Open **http://127.0.0.1:3000**. Node 22.13+ and Python 3.10+ are required. The existing workspace already has dependencies and model weights. `OPENROUTER_API_KEY` stays in the server's `.env`. For a production build locally, use `npm run build` and `npm start`.

## Use

- **Archive**: `archive/` is the official source, imported recursively at startup. Root photographs are general Chikukwa references; `Chikukwa Water Sites/` (including `sacred water sites/`) supplies water references; `collages-style-guide/` supplies composition references; `people/` supplies direct people cutouts. Select images to constrain the random category sampling, or leave the selection empty. Original files and older studies are retained; old sample images are excluded from new official selections.
- **Research archive**: the Archive → Research collection indexes `training-data/scripts/*.txt` and `training-data/papers/*.pdf` locally. Originals stay in place; no pages or illustrations are pasted into a collage. Choose **2–10 research files** in Options (default **4**). Selection ranks passages against the request and contributor text; archive checkboxes optionally constrain the eligible pool. Missing/unreadable files and insufficient selections stop before paid calls.
- **Context**: three prompts guide every creation. The **system prompt** (art direction) loads `training-data/system_prompt.txt` and stays editable here; “Restore project default” reloads it, and a replaced default is kept in `data/studio.json` under `systemPromptHistory`. The **technical rules** in `training-data/technical_prompt.txt` are binding, shown read-only, and sent first to every model call: they take precedence over the art direction, the request and all source text (archive and reference rules, people-only direct pixels, research, segment → treat → crop, coverage, ground, layer limits, cultural safeguards, provenance). Change them by editing the file. The **user prompt**, “Describe your image”, starts from `training-data/image_prompt.txt`. Add contributor accounts, relationships and constraints as text for this work. The creative sections of `brief.md` remain supporting context; the MOU's legal sections and private folder links are excluded from model context.
- **Options**: choose **6–20 distinct images** (default **10**), whether archive people cutouts appear in the collage, individual material treatments and image model. Treatment choices persist in this browser; uncheck anything you dislike, or clear all treatments. **Include people** is on by default. Archive images still inform the VLM when final archive inclusion is off. **Torn paper edges** (on by default) let the planner give broad generated fragments a torn printed-paper edge; people always keep clean cutouts. Multiple crops of one image do not count as separate images.
- Enter a prompt and create. **Studies** retains attempts and cost records. **How this image was made** contains the advance JSON plan, research, transformations, actual cutouts, draft, review and coverage check.
- **Edit** supports placement, rotation, opacity, polygon cuts and undo/redo on assembled fragments. Raw archive photographs cannot be pasted from the archive gallery. **Save image** exports a 2400 × 1500 PNG. **View** hides the interface; Escape restores it.

The first startup imports and normalizes the official archive and can take several minutes. Subsequent startups reuse unchanged images. Duplicate files count as one photograph; if a file is also in `people/`, it is assigned to direct cutout use. Import errors are reported in the server log.

Photographs are kept locally: `archive/` and `images_test/` are excluded from Git. A fresh checkout needs the official archive copied into `archive/` before starting the app. Automated tests use synthetic images and do not require the private archive; the optional paid live test requires local sample photos in `images_test/`.

## Automatic sequence

1. Randomly sample distinct official photographs within each category, without replacement. Use 2 general Chikukwa references and 2 water references (3 and 3 above 12 images, so 3–6 in total), including the sacred-water subfolder in the water pool. Select exactly one collage to inform composition only. With people enabled, use `min(8, max(4, round(count × 0.4)), count − 3)` people photographs; if only two or three are eligible, use those, but stop before paid calls if fewer than two are available. This gives three people sources for a six-image composition and eight for a twenty-image composition. A top-level `open-access` folder is imported but never used as a reference until its licences are recorded. All remaining components are generated environment/material images. Each generated component receives one general and one water reference, cycling through the randomly sampled pools so every selected reference reaches the image model. Context/reference photographs do not count as final components. Category shortages, disabled references, or people inclusion without archive inclusion stop before paid calls.
2. Verify current provider availability, structured-output support, prices and **the complete sequence's cost before any paid call**.
3. Select 3–6 relevant local research passages before paid work (default 4), one from each of the most relevant files in `training-data/scripts/` and `training-data/papers/`, retaining filenames, checksums and page/line locations. The explicit non-disclosure testimony contributes only an editorial restriction summary and never leads an image. Read these passages with the request, art direction, creative brief and supplied text using Qwen, supplemented by Exa search. Findings require returned URL annotations.
4. A Qwen VLM sees the actual archive images, their metadata, the supplied texts and research. The retrieved originals and required generations occupy fixed source slots, and each image is paired explicitly with its slot to prevent subject/source swaps. It writes an **advance JSON plan**: source IDs or generation prompts, reference IDs, extraction subjects, transformation types/reasons, boundary treatment, normalized position, scale, rotation and layer order. Duplicate originals and permission violations stop execution.
5. The plan must cite every selected passage for composition and give each one the visual relationship or layout consequence it creates in `researchComposition.relationships`. Each passage that can lead an image leads its own generated part (at least two, one passage per part), with a concrete interpretation. Generated prompts ask for a speculative photograph anchored in observed archive detail and rendered photographically. Each image gives one primary cut, and generated images also give fixed detail cuts at other scales, so a collage has 12–21 fragments aiming at 3–5 dominant, 4–7 medium and 5–9 small ones without extra image calls; a missed tier target is reported, not fatal. Details share their image's treatment. The visual critique checks the research-led parts, the relationships and the scale hierarchy, and fragments it omits keep their draft placement. Provenance retains the source snapshots, per-part links and relationships. People are never generated: SAM crops complete visible people or groups directly from the selected people photographs, preserving their appearance, always with clean edges. People and collage-style photographs are excluded from image-generation references even if their reference permission is enabled. The single collage reference is shown to the visual planner for layout, scale, overlap and rhythm only. General/water references default to generation permission; people default to crop permission. Contributor permission edits survive reimports.
6. When any treatment is enabled, every generated fragment receives exactly one clearly visible treatment at strength 0.5–1 (the planner aims for 0.6–0.9), with at most three treatment kinds per collage. Options include water refraction, reflection echoes, sediment washes, capillary staining, contour impressions, paper grain, copy softness, offset inks, tonal steps, eroded impressions and an earth/water palette wash. A fourth proposed kind is folded into the strongest chosen kind and recorded in `treatmentAdjustments`. Texture effects scale with the image so they survive reduction into the collage; tonal steps keep hues. All-off produces untreated generated material. People stay untransformed. Originals remain intact and every fragment records its parent, root, treatment and reason.
7. **Segment → treat → crop.** The VLM sees the untreated images and supplies boxes and positive points; SAM segments the untreated image. The planned treatment is then applied to the whole image and cropped with SAM's exact crop box and alpha, so effects keep their scale and the mask is unaffected by the treatment. It declares whether coordinates use pixels or a 0–1000 grid; the server resolves inconsistent declarations against the actual supplied dimensions and records the result. For an archive person or group, the VLM must request the whole visible figure and YOLO replaces its box with full-person detections; an uncertain human fragment is rejected. SAM 2.1 then performs segmentation. A **silhouette** uses its alpha mask; **residue** expands the mask slightly; a **field** expands the SAM mask while retaining an irregular alpha edge and transparent corners. Automatic collages do not use whole rectangular photographs. The local worker rejects near-whole masks, limits environmental field expansion to the composition-directed subject, and the server checks actual alpha pixels before accepting a cut. Opaque rectangular results or cuts retaining more than 92% of the original are saved as failed parts for local retry; they are never pasted as a fallback.
8. Assemble the actual cuts using the advance plan, with at least two generated environmental fields sharing the ground. A VLM reviews the contact sheet, rendered draft and alpha-based visibility measurements. No single fragment may occupy more than 58% of the working canvas area. Local repair can shrink, enlarge within that cap, move and reorder cuts to expose hidden material; it also runs on fully covered canvases when sources are obscured.
9. Check actual mask coverage, each root image's visible contribution and the fraction remaining visible after overlap. Aim for **at least 99.5% canvas coverage**, every source contributing visibly, and at least 25% of each on-canvas fragment remaining visible. Legibility and the per-layer area cap take priority over filling the last gap. Automatic placement also caps enlargement at 2× the working pixels. Exposed canvas uses a deep water-green ground (`#183f3b`) by default; white, cream and pale-grey backgrounds are replaced consistently in planning, saved projects, previews and exports. Natural photographic highlights and archive people remain untouched. The coloured ground does not count as image coverage. Residual holes or heavily obscured sources are reported with the completed study; no extra paid repair loop runs.
10. If SAM times out, retry it once locally at a smaller working size. If that also fails, save the component as a failed part and compose the study from every successful component. **Retry part** reruns local detection and SAM against the saved image without repeating research, planning or generation; **Ignore** accepts the omission. If every local cut fails, the study record and all source material remain available, and the first successful part retry creates its canvas.

Plan coordinates use a 1600 × 1000 working canvas. Positions are centers; width is a canvas-width fraction, and height preserves aspect ratio. The final project stores exact rendered layer geometry, including coverage adjustments. The coverage audit samples alpha at 320 × 200; each counted root must contribute at least 0.2% of the canvas after occlusion. Layout fitting uses a 160 × 100 alpha grid and the final audit uses 320 × 200. This is a quantitative check, not a guarantee of artistic quality.

## Models and the cost limit

| Role | Model |
| --- | --- |
| Research | Qwen3 30B A3B Instruct + Exa |
| Advance visual plan, transformed-image grounding, review | Qwen3 VL 235B A22B Instruct |
| Fixed-price 2K source generation | Seedream 4.5 |
| Premium choice | GPT Image 2.5 Sunburst — currently blocked: its variable pricing has no enforceable per-image maximum |
| Local detection / cutting | YOLO11n / SAM 2.1 tiny |

The app has four language/vision steps plus the required image calls. Before work starts, it checks prices and capabilities and selects up to three eligible providers per text/vision step, as the complete workflow budget allows. Providers are ordered by reported uptime, throughput and latency; equal-health providers are shuffled, and providers that failed earlier in the same study are tried last. A more expensive provider can run first. Rate limits, temporary upstream failures, network timeouts and unreadable API responses (including empty, truncated or non-JSON bodies with a successful HTTP status) automatically switch to the next checked provider without restarting the study. Each request has a 300-second deadline. OpenRouter sends HTTP 200 before a slow provider finishes, so the deadline covers the whole response; a request that runs past it is recorded as a timeout, not an unreadable response, and switches provider. If every checked provider fails the final layout review, the study completes with the already rendered draft arrangement and a warning. Explicit provider image-count limits also trigger fallback; so do answers cut off at their output-token limit and answers that are not valid JSON (the call is paid and recorded; another provider answers). Response schemas use only the JSON Schema keywords every checked provider's grammar engine has accepted (`server/structured.js`; a test audits every schema), and a provider that still rejects a grammar is replaced by the next one. An answer a step cannot use (wrong structure or values) also counts as a failed attempt, so the next provider answers. Paid plans are repaired before that point where it is safe: numbers just outside a placement or treatment range are clamped, invalid detail cuts are skipped with a warning (details are optional), and the layer order is completed. An unusable layout review keeps the draft collage. `node scripts/check-structured-outputs.mjs` sends each schema to every provider a study would use, with at most 16 output tokens, to confirm this against the live providers. Other invalid-input errors, authentication and credit errors stop the process. The planner's output limit grows with the collage (2,000 + 900 tokens per image, up to 16,000), so a full plan fits. Known input-image limits are checked against each step before paid work and again before sending a request. Venice’s Qwen3 VL endpoint is excluded above 10 input images. A default 10-image collage supplies 13 archive references to planning; all references remain present when routing to an alternative. Image calls still use one pinned provider.

Each creation has a spending ceiling of **$5.00 by default**; set `CREATION_COST_LIMIT` in `.env` to change it. The **ceiling includes every possible provider attempt**, reserving full provider context at enforced input/output price ceilings, bounded completion tokens, an Exa allowance per research attempt, and 20% price headroom. Every reservation is persisted before sending its request. Failed or unreported calls retain their reservations; cheaper actual usage is not recycled into extra calls. Each text request pins one provider using [OpenRouter's provider controls](https://openrouter.ai/docs/guides/routing/provider-selection); the app handles the bounded failover itself so each attempt is accounted for. Repeated request IDs return the same job.

The number of affordable new images depends on current quotes. If the complete requested configuration cannot fit the ceiling, it stops before charging. Larger collages increase both the reference pools and the number of direct people sources, up to eight. Context/reference images do not count unless their pixels contribute to the final collage.

**Premium limitation:** OpenAI describes GPT Image 2.5 Sunburst as its most capable image generation/editing model. Its current OpenRouter endpoint charges variable image tokens and exposes no enforceable per-image maximum. The option is visible, but creation stops before any research or generation charges. It is not silently downgraded, and the app does not claim to reproduce ChatGPT's complete workflow. A verifiable bounded provider quote is needed before this option can run within the strict ceiling.

Prices and provider capabilities are verified at runtime; model names are not a promise of permanent availability. The ceiling relies on providers honoring advertised prices. Unexpected over-billing stops further calls. Local electricity and OpenRouter credit-purchase fees are outside API usage accounting.

## Storage and permissions

`data/studio.json` holds the shared archive, saved text, projects, studies and ledgers; writes are atomic. Back up the entire `data` directory, because project JSON references image files. Use one server process. A restart retains reservations and never retries paid calls automatically. Studies that had reached local cutting are restored with per-part retry controls using their saved transformed images and VLM observations.

Uploads accept JPEG, PNG, WebP, AVIF, HEIC and TIFF when supported by the decoder, up to 20 MB and 60 megapixels. `ARCHIVE_DIR=./archive` imports the official directory recursively at startup; an absolute override must use the same category folders. The legacy `./images_test` setting is automatically migrated to `./archive`. Add official images to the appropriate folder and restart the server. **Use full archive is the default:** no image selection is needed, and new imports join the pool automatically. Each collage samples the required category counts from that pool. Choose specific images is an optional restriction. New official Chikukwa/water imports permit generation references, collage images guide composition, and people permit direct cutouts; people and collage images are never generation references. Unchanged imports preserve edited permissions and metadata; removed files leave historical assets available to old studies but are excluded from future selections. Originals remain private; working PNGs strip EXIF/GPS and fit within 4096 pixels. Public media routes expose working images only.

VLM analysis sends normalized working copies to OpenRouter. Generation references and transformations have separate per-image permissions. Keep sensitive/contextual restrictions in contributor metadata. Metadata is evidence for models, not executable instructions. Research is used as prompt context, not model training. PDF text extraction uses [Mozilla PDF.js](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs); scanned documents without readable text need an OCR text version. No fine-tuning, video, seam inpainting, web-image harvesting or physically printed/scanned transformations are implemented.

## Verify

```sh
npm test
npm run build
npm run test:ui
```

These tests make no paid calls. They cover recursive official imports, random category quotas, direct people crops, composition-only references, and environment-only generation; distinct-image counts; reference and transformation permissions; grounding after transformation; alpha coverage; provider failover and budget rejection; archive/context persistence; editing; export; desktop/mobile UI.

`RUN_LIVE_AI=1 node tests/live-pipeline.mjs` explicitly runs a paid integration test in an isolated `test-results/dense-studio` archive. It copies the five test images, permits those copies as generation references, and tests six distinct source images with one new generation. Successful API responses are cached for debugging. Normal app requests never use that cache; only the bounded provider failover described above retries paid text requests. Live artifacts do not replace your current arrangement.
